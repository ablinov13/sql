# Лабы по БД на C++: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Лабы 0, 1, 2, 3.1, 4, 5 на C++ (VS 2022) с данными «книжный магазин», отчёты `.docx` по образцам, пояснительные записки, скриншоты реальных запусков.

**Architecture:** Одно решение `DbLabs.sln`: статическая библиотека `sqlite` (amalgamation) и по консольному проекту на каждую лабу. Данные в `data/`, рабочий каталог отладки — `$(SolutionDir)`. Отчёты генерируются python-скриптом из копии образца `.docx`.

**Tech Stack:** MSVC v143, C++17, SQLite 3.50.4 C API, sqlite_orm 1.9.1, WinSock2, Node.js (только для JS-демо), Python 3.12 + python-docx + Pillow (только для отчётов и скриншотов).

**Spec:** `docs/superpowers/specs/2026-10-25-db-labs-design.md`

## Global Constraints

- VS 2022, toolset v143, x64, `/std:c++17`, `/utf-8`, без precompiled headers. Собирается без vcpkg и без ручной настройки.
- Рабочий каталог отладки (`LocalDebuggerWorkingDirectory`) = `$(SolutionDir)`. Программы читают `data/books.txt` и `data/authors.txt` относительно него и пишут `labN.db` туда же (`*.db` добавить в `.gitignore`).
- Первая строка каждого `main`: `SetConsoleOutputCP(CP_UTF8);`.
- Лабы 3 и 4: в DAO и хранилище нет `cout`/`printf`/`try`/`catch`. Ошибки → `throw`; ловит и печатает только `main`.
- Отчёты: копия образца, стили сохранены, ФИО/группа/руководитель пустые.
- Код простой и закомментирован по-русски: студент должен суметь объяснить каждую строку.

## Данные (решено здесь)

- `data/books.txt`: `title,genre,price,year,author`, 25 строк, без заголовка, UTF-8 без BOM, без запятых внутри значений. 6–8 жанров, цены 300–2500, примерно 10 авторов, у некоторых по 3–4 книги.
- `data/authors.txt`: `name,country`, по строке на каждого автора из `books.txt`.
- Лабы 1, 2 и 5: одна таблица `books(title TEXT, genre TEXT, price INTEGER, year INTEGER, author TEXT)`.
- Лабы 3 и 4: `authors(id INTEGER PK, name TEXT, country TEXT)`, `books(id INTEGER PK, title, genre, price, year, author_id INTEGER REFERENCES authors(id))`.

## Review Focus

1. Русский текст (кириллица в данных) должен правильно отображаться в консоли VS и в браузере. Проверка: в выводе каждой программы есть кириллица, на скриншоте она читается.
2. Запуск через F5 из VS, а не только из командной строки: если рабочий каталог неверный, файл данных не найден. Программа должна вывести понятную ошибку «не найден файл data/books.txt» и вернуть 1, а не упасть. Проверка: запустить exe из другого каталога и увидеть это сообщение.
3. Повторный запуск: БД уже существует. Ожидание — тот же результат без дублей (DROP/`remove`, затем пересоздание). Проверка: запустить дважды и сравнить число строк.
4. Порт 3000 занят (например, запущен JS-демо): сервер печатает ошибку bind и завершается, а не висит молча. Проверка: запустить два сервера.
5. Пустая или кривая строка в `books.txt` (пустая строка в конце, `\r\n`): пропускается, не ломает загрузку. Проверка: в файле CRLF и пустая последняя строка, загружено ровно 25.

**Interfaces (Produces, лаба 4 повторяет модели):**
- `struct Author { int id = 0; std::string name; std::string country; };`
