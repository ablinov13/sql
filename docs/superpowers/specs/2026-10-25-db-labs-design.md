# Лабораторные по базам данных (0–5) на C++: дизайн

Дата: 2026-10-25

## Зачем и что нужно

Студенту (23-ПМ, НГТУ, дисциплина «Базы данных») нужно сдать лабораторные 0, 1, 2, 3.1, 4 и 5 по слайдам преподавателя. Преподаватель разрешил любой язык, студент выбрал **C++**. Всё должно собираться и запускаться в **Visual Studio 2022** на ноутбуке студента: это та же машина, на которой идёт работа (VS 2022 Community, Node.js и Python там установлены).

Что сдаётся:
1. Код всех лаб с программированием.
2. **Отчёты `.docx` в точности как образцы** `Лаба1 (4).docx` и `Лаба2 (2).docx`: титульник НГТУ, оглавление, «Цель и задачи», «Ход работы», «Вывод», «Приложение А» с кодом. Студент сам впишет ФИО, группу и руководителя и поправит, что ему нужно.
3. **Пояснительные записки** для самого студента: что сделано, какие методы и зачем нужны. Нужно, чтобы студент понимал свой код на защите.
4. Реальные скриншоты результатов, обрезанные и вставленные в отчёты.

Образцы написаны другим студентом на тему «автомобили», а Лаба 2 там на Python. Это только пример оформления, содержание и тема нужны свои.

## Цели / не-цели / анти-цели

**Цели:** всё компилируется в VS 2022 без установки чего-либо (зависимости лежат в репозитории), выполнены все пункты каждого слайда, код простой и понятный студенту.

**Не-цели:** промышленная архитектура, тесты, кроссплатформенность, CMake.

**Анти-цели (провал, даже если работает):**
- проект требует vcpkg или ручной настройки путей и не собирается «из коробки»;
- в лабе 3/4 есть `cout` или `try/catch` внутри DAO (прямо запрещено слайдом «Замечания»);
- кракозябры вместо русского текста в консоли или в браузере;
- отчёт заметно отличается от образца по оформлению;
- код слишком умный: студент не сможет объяснить его на защите.

## Предметная область (выбрал Claude, студент поручил)

**Книжный магазин.**

- `books`: `title` (TEXT, название), `genre` (TEXT, категория), `price` (INTEGER, цена в рублях), `year` (INTEGER, год издания). 25 книг, названия на русском, 6–8 повторяющихся жанров (Фантастика, Детектив, Роман, Фэнтези, Классика, Научпоп…). Цены 300–2500, чтобы можно было делать выборки по диапазонам.
- Для лаб 3 и 4 (слайд лабы 4: «DAO с двумя таблицами») добавляется `authors` (`id`, `name`, `country`), в `books` появляются `id` и `author_id`. Около 10 авторов, у части по нескольку книг, чтобы JOIN и GROUP BY давали осмысленный результат.

## Лабы

### Лаба 0: данные
`data/books.txt`: строки `title,genre,price,year` через запятую, без запятых внутри значений. В записке примеры `grep` по файлу (по жанру, по году): слайд упоминает «предыдущее задание (с grep)». Для лаб 3/4 рядом лежит `data/authors.txt`, а в `books.txt` для них используется расширенный вариант с автором (формат на усмотрение исполнителя, главное одинаковый в лабах 3 и 4).

### Лаба 1: SQLite-клиент + SQL
`lab1/lab1.sql`: `CREATE TABLE books`, `INSERT` всех 25 строк, 3 запроса `SELECT`. Запросы свои, не копия образца: WHERE с условием по жанру и цене, ORDER BY + LIMIT, GROUP BY жанр с COUNT/AVG. Клиент для отчёта — DB Browser for SQLite, как в образце. Если его нет на машине, скриншоты делаются из `sqlite3` CLI (есть в msys64), в отчёте тогда так и написано.

### Лаба 2: C++ + встраиваемая БД
Слайд требует JDBC/H2 для Java. Для C++ аналог — **SQLite C API** (как в образце, где взяли sqlite3 для Python). Программа открывает `books.db`, делает DROP/CREATE, читает `books.txt`, вставляет строки через подготовленный запрос (`sqlite3_prepare_v2` / `bind` / `step`) в одной транзакции и выполняет 3 запроса SELECT с выводом в консоль. Здесь код процедурный, всё в `main`.

### Лаба 3.1: DAO
Код лабы 2 переписывается на DAO:
- структуры `Book`, `Author`;
- RAII-класс подключения к БД (закрывает соединение в деструкторе);
- `AuthorDao`, `BookDao`: `createTable`, `insert(const Xxx&)`, `getAll()`, плюс 1–2 выборки (`getByGenre`, `getByPriceRange`, книги с именем автора через JOIN). Возвращают `std::vector<Xxx>`.
- **Слайд «Замечания» обязателен:** в DAO нет `cout`/`printf`, ошибки SQLite превращаются в исключение (`std::runtime_error` или свой класс) и пробрасываются наверх. Ловятся и печатаются только в `main`, весь вывод тоже только в `main`.
- `main`: создаём объекты → `XxxDao.insert` → `XxxDao.getXxx` → перебираем вектор и печатаем.

### Лаба 4: ORM
Тот же код с двумя таблицами переводится на ORM. Для C++ ORMLite (Java) заменяется на **sqlite_orm** (header-only, один файл, C++17). `make_storage` с описанием двух таблиц, `sync_schema`, `insert` объектов (20–30 книг), 2–3 осмысленных запроса через API ORM: группировка по жанру (count/avg цены), диапазон цен или годов, JOIN книг с авторами. Правила «Замечаний» соблюдаются и здесь.

### Лаба 5: HTTP
- 5.0.1 и 5.0.2: в папку кладутся `http-hello.js` и `http-hello-html.js` (перепечатаны со слайда, http-hello.js — стандартный минимальный вариант с text/plain) и инструкция `node http-hello.js`. Рядом их C++-аналоги на WinSock. Студент согласился с этим вариантом.
- 5.0.3 (главное): C++-сервер на WinSock на порту 3000 **по схеме http-hello-html**: заголовок `200 OK` + `text/html; charset=utf-8`, потом head/body, `<table>` с книгами из `books.txt` и закрывающие теги. Простой CSS для таблицы допустим. Проверка: `http://localhost:3000/` в браузере.

## Структура и сборка (решения Claude)

```
sql/
  DbLabs.sln                 — одно решение, проект на каждую лабу
  data/books.txt, authors.txt
  third_party/sqlite/        — sqlite3.c, sqlite3.h (amalgamation)
  third_party/sqlite_orm/    — sqlite_orm.h
  lab1/ lab1.sql
  lab2/ lab3/ lab4/ lab5_1/ lab5_2/ lab5_3/ (+ .js для 5)
  reports/                   — Лаба1.docx … Лаба5.docx
  notes/ или ПОЯСНЕНИЕ.md в каждой папке лабы
```
- Toolset v143, x64, C++17, `/utf-8`. `sqlite3.c` компилируется как C внутри проекта (без precompiled headers).
- Путь к `data/` задаётся так, чтобы F5 из VS работал без настройки: `$(SolutionDir)` как рабочий каталог отладки или копирование данных в каталог вывода.
- Консоль: `SetConsoleOutputCP(CP_UTF8)`, исходники в UTF-8.
- Сборка каждого проекта проверяется здесь через MSBuild, каждая программа запускается.

## Скриншоты и отчёты

- Консольные результаты: реальный запуск собранного exe здесь. Скриншот окна консоли, обрезанный до полезной области. Если окно консоли снять нельзя, рендерится PNG из реального вывода в стиле консоли.
- Лаба 5: скриншот страницы `localhost:3000` во встроенном браузере.
- Отчёты собираются на основе образца `.docx`, чтобы сохранить стили, титульник и поля: копия образца, тело заменяется python-docx'ом. Поля ФИО/группа/руководитель пустые, как в `Лаба2 (2).docx`. Оглавление — поле Word, обновляется при открытии (или F9). Код целиком идёт в «Приложение А».
- Лаба 0 отдельного отчёта не получает (в образцах его нет), её данные описаны в отчёте лабы 1.
