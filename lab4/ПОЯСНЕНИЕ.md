# Лаба 4: ORM

## Что требовалось
- Перевести код лабы 3 (DAO с двумя таблицами) на механизм ORM.
- Фреймворк любой. Преподаватель рекомендует ORMLite, но он только для Java.
- Как и раньше: создать структуру базы, добавить элементы (20–30, колонки — строки и числа, с возможностью группировать по повторяющимся значениям и диапазонам) и сделать 2–3 осмысленных запроса.

## Что такое ORM
**ORM (Object-Relational Mapping)** — «отображение объектов на таблицы». Мы один раз описываем, какой структуре соответствует какая таблица и какому полю какая колонка. Дальше библиотека сама пишет SQL:
- `storage.insert(book)` превращается в `INSERT INTO books (...) VALUES (...)`;
- `storage.get_all<Book>(...)` превращается в `SELECT ...` и возвращает `std::vector<Book>`, то есть сразу готовые объекты.

Сравнение с лабой 3:

| Лаба 3 (DAO вручную) | Лаба 4 (ORM) |
|---|---|
| сами пишем `CREATE TABLE` | `make_table(...)` + `sync_schema()` |
| сами пишем `INSERT ... (?, ?, ...)` и `bind` | `storage.insert(объект)` |
| сами читаем колонки `columnText(1)`, `columnInt(3)` в поля | ORM заполняет поля сама |
| классы `Database`, `Statement`, `AuthorDao`, `BookDao` | один объект `storage` |
| ~200 строк вспомогательного кода | ~25 строк описания в `Storage.h` |

## Почему sqlite_orm
Для C++ нет ORMLite, а **sqlite_orm** — самая близкая по духу библиотека: лёгкая и для SQLite. Она состоит из одного заголовочного файла `third_party/sqlite_orm/sqlite_orm.h`, ничего устанавливать не надо. Требует C++17 (включён в `common.props`).

## Файлы
- [Models.h](Models.h) — те же `Author` и `Book`, что в лабе 3. Это обычные структуры, ORM не требует ничего наследовать.
- [Storage.h](Storage.h) — описание базы:
  - `make_storage("lab4.db", таблицы...)` — хранилище: БД и список таблиц;
  - `make_table("books", колонки...)` — таблица;
  - `make_column("price", &Book::price)` — колонка `price` хранится в поле `Book::price`. `&Book::price` — указатель на поле класса, по нему ORM знает, куда класть значение;
  - `primary_key().autoincrement()` — первичный ключ с автонумерацией;
  - `unique()` — имена авторов не повторяются;
  - `foreign_key(&Book::authorId).references(&Author::id)` — внешний ключ на авторов.

  `using Storage = decltype(makeStorage(""))` нужен потому, что тип хранилища — огромный шаблон. `decltype` берёт его у функции, чтобы не писать вручную.
- [main.cpp](main.cpp) — всё остальное.

## Порядок в main
1. `std::remove("lab4.db")` — удалить старую базу, чтобы при повторном запуске не было дублей.
2. `storage.sync_schema()` — ORM создаёт таблицы по описанию.
3. `storage.transaction([&]{ ... return true; })` — все вставки одной транзакцией. Лямбда возвращает `true`, и это означает COMMIT.
   - Автор: `Author author{0, имя, страна}; storage.insert(author);` (id = 0, база сама назначит номер).
   - Книга: сначала найти автора `storage.get_all<Author>(where(c(&Author::name) == имя))`, взять его `id`, потом `storage.insert(book)`.
4. `storage.count<Book>()` — количество строк (`SELECT COUNT(*)`).

## Запросы (осмысленные)
1. **Группировка по повторяющимся значениям:** сколько книг каждого жанра и какая средняя цена.
   ```cpp
   storage.select(columns(&Book::genre, count(&Book::id), avg(&Book::price)),
                  group_by(&Book::genre), order_by(count(&Book::id)).desc());
   ```
   Результат — вектор кортежей `(жанр, количество, средняя)`. Его удобно разбирать так: `for (const auto& [genre, booksCount, avgPrice] : ...)` (structured bindings, C++17).
2. **Диапазон:** книги от 500 до 700 ₽.
   ```cpp
   storage.get_all<Book>(where(between(&Book::price, 500, 700)), order_by(&Book::price));
   ```
3. **Две таблицы:** книги британских авторов.
   ```cpp
   storage.select(columns(&Author::name, &Book::title, &Book::year),
                  inner_join<Author>(on(c(&Book::authorId) == &Author::id)),
                  where(c(&Author::country) == "Великобритания"),
                  multi_order_by(order_by(&Author::name), order_by(&Book::year)));
   ```
   `c(...)` оборачивает поле, чтобы можно было писать условия через `==`. `multi_order_by` нужен для сортировки по двум полям.

## Ошибки
Правила из лабы 3 действуют и здесь: вывод и `try/catch` только в `main`. sqlite_orm сообщает об ошибках БД через `std::system_error`, поэтому первым стоит `catch (const std::system_error&)`, а потом общий `std::exception` (например, нет файла данных).

## Настройка, которая понадобилась
В `common.props` добавлен макрос `_SILENCE_CXX17_CODECVT_HEADER_DEPRECATION_WARNING`. sqlite_orm использует `<codecvt>`, который в C++17 помечен устаревшим, а с включённой в VS проверкой SDL это предупреждение превращается в ошибку.
